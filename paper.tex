\begin{abstract}
Autoregressive language-model inference is limited by attention cost and by the
key-value (KV) cache, which grows linearly with context length.  This group
project implements and evaluates several training-free acceleration strategies
for Pythia-70M: a baseline SDPA runner, a reduced-KV grouped-query attention
(GQA) conversion, KVPress-Knorm, KVPress-StreamingLLM, and an additional
layer-wise sink-plus-recent KV compression prototype.  We evaluate WikiText-103
and one PG-19 test sample using chunked perplexity, cached continuation
perplexity, TTFT, TPOT, throughput, and approximate KV-cache memory.  The main
finding is deliberately conservative: KV cache compression can improve CPU
throughput in selected settings, while naive training-free GQA reduces memory
but severely damages quality.  The code is available at
\url{https://github.com/lilfry09/Training-free-LM-inference-acceleration-group/tree/layerwise-compression}.
\end{abstract}

\section{Introduction}

The KV cache is essential for fast autoregressive decoding because each new
token can reuse keys and values from previous tokens.  However, this cache also
creates a memory and attention bottleneck: for a model with $N$ layers, context
length $L$, KV heads $H_{kv}$, and head dimension $d$, the cache is proportional
to $2NLH_{kv}d$.  The course assignment asks for training-free acceleration on
Pythia-70M, so the central question is not whether we can train a better
architecture, but which drop-in modifications remain honest and reproducible.

We integrate methods from two families.  First, reduced-KV GQA stores fewer
cached key/value heads, inspired by uptrained GQA models~\citep{ainslie2023gqa}.
Second, KV-cache compression removes token positions from the sequence
dimension, following the StreamingLLM attention-sink idea~\citep{xiao2023streamingllm}
and the KVPress implementation~\citep{kvpress2024}.  We also implement a simple
layer-wise schedule that keeps more cache in shallow layers, compresses middle
layers aggressively, and keeps a moderate budget in deep layers.

Our contributions are: (1) a reproducible Pythia-70M evaluation framework for
baseline, GQA, KVPress-Knorm, KVPress-StreamingLLM, and layer-wise compression;
(2) quality, speed, and memory measurements on WikiText and PG-19; and (3)
negative-result analysis showing that training-free reduced-KV GQA is not a
reliable accelerator for a pretrained MHA checkpoint.

\section{Methods}

\paragraph{Baseline.}
The baseline loads the local EleutherAI Pythia-70M checkpoint through Hugging
Face Transformers and uses scaled dot-product attention.  Model parameters are
never changed.

\paragraph{Reduced-KV GQA.}
Pythia-70M has 8 attention heads.  Our GQA variant computes the original query,
key, and value states, averages key/value heads into 2 cached KV heads, stores
the reduced tensors in the dynamic cache, and evaluates grouped attention with
PyTorch SDPA.  This is a training-free conversion, not the uptraining recipe of
\citet{ainslie2023gqa}; therefore we treat it as a stress test and include a KV
head sanity check.

\paragraph{KVPress compression.}
We evaluate KVPress-Knorm and KVPress-StreamingLLM at removal ratio 0.5.
Knorm keeps cache entries with larger key-norm scores.  StreamingLLM keeps sink
tokens and recent tokens.  Compression is applied after prefill through
GPT-NeoX attention hooks, and the code records per-layer before/after cache
lengths.

\paragraph{Layer-wise prototype.}
The additional prototype uses a deterministic sink-plus-recent selector with
layer-specific keep ratios: shallow layers keep 80\%, middle layers keep 50\%,
and deep layers keep 70\%.  It compresses once after prompt prefill and then
continues greedy decoding with the compressed cache.

\section{Experiments}

\paragraph{Setup and metrics.}
All experiments use Pythia-70M, no training, CPU inference, and greedy decoding.
WikiText uses the first 4096 tokens from the test split.  PG-19 uses the first
test example and takes the first 4096 Pythia tokens.  Chunked PPL resets context
every 512 tokens and is used for baseline/GQA quality.  Cached PPL prefills 512
tokens, optionally compresses the cache, and scores the next 256 true tokens one
by one.  Speed uses 128, 512, and 1024 prompt tokens, one warm-up, three measured
runs, and 64 generated tokens.  We report TTFT, TPOT, throughput, and approximate
KV memory.  The main reproduction command is \texttt{.\textbackslash scripts\textbackslash run\_matrix.ps1}.

Table 1 shows the key quality result.  GQA-2KV is a clear
negative result: reducing 8 KV heads to 2 by averaging severely breaks the
learned attention geometry.  KVPress has a more useful trade-off.  On PG-19,
StreamingLLM-0.5 preserves cached PPL nearly exactly (29.60 to 29.49), while
Knorm degrades it mildly.  On WikiText, both KVPress variants hurt cached PPL,
which shows that compression quality depends on the text slice and selector.

KVPress-StreamingLLM improves WikiText throughput at 128 and 512 tokens, and

we report raw TTFT/TPOT/throughput tables in \texttt{outputs/comparison\_speed.md}
and avoid claiming universal acceleration.

The diagnostics in Table 3 support two claims.  First, the
GQA path is numerically sane at 8 KV heads, then collapses as heads are reduced;
the failure is the training-free conversion itself, not the grouped-attention
implementation.  Second, stronger StreamingLLM compression reduces memory but
can worsen cached PPL.  The layer-wise prototype further tests a heterogeneous
budget: on a quick WikiText run it reduces cache by 28.4\% and improves
throughput from 16.89 to 36.41 tokens/s with PPL 80.36 to 82.30; on PG-19 it
keeps the same cache reduction but slows down, again reinforcing that CPU speed
depends on workload and overhead.

\section{Conclusion}

This study finds that not every training-free memory reduction is a valid
accelerator.  Naive reduced-KV GQA saves cache memory but breaks Pythia-70M
quality.  KVPress-style token compression is more promising and sometimes
improves throughput, but its benefit is sensitive to dataset, context length,
and implementation overhead.  The best-supported conclusion is therefore an
honest engineering one: KV cache compression is worth evaluating carefully under
the target inference stack, while untrained architectural conversion should be
treated as a negative baseline unless quality is repaired.
